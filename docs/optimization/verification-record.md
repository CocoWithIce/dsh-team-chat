## 8. 真实载荷缺陷链：t30 → t31 → t32（合成测试掩盖生产缺陷）

> **本节的定位**：记录本次改造中**最有价值的一条验证教训** —— 一条被合成测试完全掩盖、由真实日志验证揪出的**生产缺陷**，及其修复与复核。**追加于 t33，未改动 §0–§7 任何结论。**

### 8.1 t30 —— 发现（真实载荷验证 · verdict=reject）

**方法**：解码真实 `session.jsonl.zstd`（多帧 zstd，按魔数 `0x28B52FFD` 逐帧解）+ 把**真实事件**喂进 `projectSteps`/`artifactOf`。非合成输入。

**核验者自测结果**（三会话独立确认）：

| 指标 | 会话1 | 会话2 | 会话3 |
|---|---|---|---|
| 真实 `tool/call` 数 | 279（合计） | — | — |
| `arguments` 为 **JSON 字符串** | **100%（0 条对象）** | 同 | 同 |
| `artifact='—'` 比例 | **78.1%** | **58.1%** | **100%** |
| 非 `—` 的取值 | **69 条全为单字符 `{`** | 同 | 同 |
| `result` / `decision` | 正常（8.6%–16.9% 思考行 / 0%） | 正常 | 正常 |

**根因（确定性）**：`artifactOf` 假设 `arguments` 是对象（`arg.command`、`arg.file_path ?? arg.path`），真实载荷是 **JSON 字符串** → 已知工具（pwsh/read/write/edit/grep/glob，220 条全带参数）取不到值 → `'—'`；未知工具走 `Object.keys(字符串)` → 取到首字符 `'{'`。事件链**没有 parse**（`session.append` 快照原样 emit）→ **运行时必然复现**，非偶发。

**判别力来源**：**「真实载荷 vs 合成输入」的对照** —— t19 的合成用例用**对象**形态 `arguments`，全绿；真实载荷用**字符串**，全错。**用合成输入验合成假设，等于没验。**（这是本链的价值核心。）

### 8.2 t31 —— 修复（implementation · completed）

**修复内容**（仅 `lib/index.js` + `test/host-events.test.mjs`）：

1. **`artifactOf` 双形态归一化**：字符串 → `trim` 空判定 → `try JSON.parse`（失败：`artifactParseFailures++` + `lastError` 记录 + 返回 `'—'`，**不抛错**）；对象 → 直接使用；其他 → `'—'`。
2. **未知工具只在「解析后的对象」上取值** → **单字符 `{` 结构性不可能再出现**（不是"这次没出现"，是无法再产生）。
3. 快照新增 `artifactParseFailures` 字段（可观测，不静默）。
4. **`JSON.parse` 放在投影时（消费侧），未进事件热回调** —— 保住 t17 的「热回调只做 O(1)」性质。

### 8.5 教训（本节核心价值，显式成段）

1. **合成测试全绿 ≠ 生产可用。** 消费平台事件/服务载荷的代码，**必须先用真实日志样本验证形状假设**：真实载荷的形态（这里是 JSON 字符串）未必等于类型系统的直觉（对象）。
2. **验证方法必须与缺陷成因同构。** t19 用对象形态的合成输入验「对象假设」，全绿；缺陷只在**字符串形态**的真实载荷上暴露。**用合成输入验合成假设，等于没验。**
3. **修复要"结构性排除"而非"这次不出现"。** t31 让未知工具只在解析后的对象上取值 → `'{'` 从"这次没出现"变成"不可能再出现"；`parse` 失败也变成了**可观测计数**（`artifactParseFailures`）而非静默降级。
4. **修复不得破坏既有性质。** `JSON.parse` 放在**投影（消费）侧**而非事件热回调，保住了 t17 的「回调只做 O(1)，重活移出热路径」。
5. **因该缺陷推迟发布** —— 如实记录：发现于真实载荷验证、修复后经同方法复核才放行。**这是流程价值，不是瑕疵**：若只跑合成用例，这个缺陷会带着 78%–100% 空产物列进入发布。

### 9.6 教训（本节核心价值，显式成段）

> 教训 1、2 为本节指定的两条核心教训；3–6 为同链上实测得出的补充教训。**其中教训 6 是可执行规则，不是口号。**

1. **形态归一化修不了字段名假设 —— 修一处不等于修一类，要按「类别」去扫全部位点。**
   t31 修的是 `string ↔ object`（**形态**），却**没有扫「假设了不存在的字段」**（**字段名**）。于是同类缺陷在**第二个位点**（`data.error.message`）再次出现：同一个项目、同一类根因、同一套合成测试全绿。**只修被指出的那一处，同类缺陷会在下一个位点重演。正确做法是按"假设了平台载荷的什么"逐位点扫，而不是按"报错的那一行"修。**

2. **样本量不足会制造假结论 —— 假结论往往长得像结论。**
   3 会话样本里 `meta.truncated` 计数为 **0**，**看起来像死代码**（可以安全删除的分支）；扩到 **27 会话**才看到 **50 处 `truncated===true`**（t37 复现：同一样本上仍为 **50**，该计数因只统计 `ok` 事件而在时间窗内稳定）。**如果当时按 3 会话的结论删掉那个分支，就会删掉一个真实在用的功能。样本量不足时得出的"不存在"，与"不存在"看起来完全一样。**

3. **"全绿"要问判别力：控制组必须能变红。**
   T1–T4 通过并不构成证据，除非**还原修复后它们会失败**。§9.4 做了这件事（还原 → T1/T2/T3 红、exit 1）。**§8 的教训是"合成输入掩盖缺陷"，本节的教训是"即使是真实载荷，也要问这条用例能否区分新旧代码"。**

4. **有计数不等于有出口。**
   R2 指出：`artifactParseFailures` / `timeouts` 曾经"被暴露但无人消费"。**宣称"不静默"必须端到端指到人能看到它的那一行 UI**，否则计数器只是把静默换了个地方存放。

5. **跨轮次比较数字，必须绑定样本快照。**
   114（E 组 27 文件）/ 164（E+F+D 44 文件）/ 165（t37，44 文件）的差异**主因是样本集合不同**，残差 ±1 来自日志实时追加，**不是任何一方在造假**。没有样本口径的数字不可复核，**会在复盘时被误读为方法分歧或数据造假**。

6. **编码前先做形状抽查 —— 这条规则必须指得出可执行的东西，不是口号。**
   两位成员（t34 本节作者、t35 工程师）**独立收敛到同一条**：新增任何平台字段访问之前，先在探针里加一条聚合断言。**可执行形式（配套工具已存在，无新增交付物）**：
   1. 打开 `docs/optimization/shape-probe.mjs`（t34 交付），在 `stat` 中为该字段加一个**聚合计数**（只计数量与键名，**不得打印字段值**）；
   2. 用**全量**日志跑：`node docs/optimization/shape-probe.mjs <所有 session.jsonl.zstd 路径>`；
   3. **判据（硬性）**：
      - 该字段的**出现次数为 0** → **不得据此判定「该字段不存在/是死代码」**，必须扩大样本（教训 2）；
      - 该字段**出现次数 > 0 但形状与代码假设不符**（类型不同、或**键名不在契约内**）→ **停止编码**，先修形状假设；
      - 只有**出现次数 > 0 且形状与假设一致**，才可写入消费代码。
   4. 写入消费代码后，按教训 3 补一条**能变红的控制组**用例（还原实现 → 用例必须失败）。
   **本规则的触发条件是可判定的**：任何新增 `data.<字段>` / `meta.<键>` 读取。**`meta` 的键空间非固定（现有 18 键），是按本规则必须走一遍的高危区。**

### 9.7 两个未闭环项（不美化）

1. **结果列长度未验证**：`errorDetailOf` 对 `message` 做 `slice(0, 80)` 截断，但 `name (code)` 头部**不截断**——对超长 `name`/`code`（本样本未出现）无上限。**t36/t37 均未实测该边界**，列为待验证假设。
2. **`meta` 键空间仍是非固定集合**：t34/t37 观察到 18 个键（`sources`/`truncated`/`url`/`statusCode`/`diffs`/`path`/`offset`/`lines`/`totalLines`/`lang`/`shape`/`paths`/`total`/`files`/`pluginId`/`packageId`/`pluginRunId` …），随工具而变。当前只读 `truncated`（布尔）是安全的；**若未来读 `meta` 的其他键，必须按本节方法重做真实载荷验证**——**本节的教训 1 恰恰说：那将是第三次同类缺陷的候选位点。**
3. **本节未覆盖**：`errorDetailMisses` 在**真实运行期**（而非测试注入）是否真的会渲染到 UI——t36/t37 验证的是代码路径与计数器存在性，**未在浏览器中肉眼确认该诊断行的实际显示**。
